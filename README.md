# Interview: три независимых стартовых комплекта

| Задание | Папка | Локальные порты | Готовность |
|---|---|---|---|
| Full-stack: 1С → PostgreSQL | [fullstack](fullstack/README.md) | HTTP mock 8093, PostgreSQL 5543 | Локальная основа готова; 1С кандидат разворачивает сам |
| ML / MLOps | [ml-mlops](ml-mlops/README.md) | Agent API 8091 | Бесплатный mock-цикл готов; реальная модель требует ключа |
| QA / SDET | [qa-sdet](qa-sdet/README.md) | LibreChat 3082, Agent API 8092 | UI и mock-цикл готовы; реальная модель требует ключа |

Каждая папка содержит свой PDF с условием, README, Compose, зависимости, контракт и данные.
Нет workspace-зависимостей, общих volumes или общих исходников во время запуска.
Можно запускать все три одновременно. Для второго кандидата той же специальности
нужно другое имя Compose-проекта (`docker compose -p candidate123 ...`) и другие порты.

## Запуск

```bash
cd ml-mlops # или qa-sdet, fullstack
cp .env.example .env
docker compose up -d --build --wait
```

Дальнейшие команды, preflight и сброс — в README соответствующего задания.
Docker/Compose достаточно для запуска выданных контейнеров; full-stack кандидат
дополнительно устанавливает 1С. Node/Python на хосте нужны для разработки.
Внешний Langfuse, GPU и платный API для mock-прогонов не нужны.
Доступ к coding agent организатор выдаёт отдельно.

## Выдача кандидатам

**Выдавайте только папку соответствующего задания**, не весь репозиторий:
ML-условие раскрывает учебный дефект, который QA должен найти самостоятельно.
После коммита можно создать три чистых архива:

```bash
bash scripts/export.sh
```

Архивы в `exports/` содержат только закоммиченные файлы выбранной папки,
без Git-истории, `.env`, node_modules, результатов предыдущих кандидатов и этого README.
Кандидат создаёт **отдельный репозиторий в своём GitHub-аккаунте** из архива
своего задания и ведёт работу там с историей коммитов. Сдаёт ссылку на репозиторий
и SHA финального коммита. Для приватного репозитория предоставляет доступ проверяющему.
Архивы выше — стартовые комплекты; сдача одного ZIP или patch не заменяет GitHub.
