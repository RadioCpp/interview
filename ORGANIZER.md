# Подготовка выдачи

## Что ещё требуется извне

- **Все задания:** доступ к coding agent; отдельный доступ к реальной модели,
  её точное имя, endpoint, квота и контакт на случай блокировки.
- **Full-stack:** кандидат сам устанавливает 1С, создаёт минимальную конфигурацию,
  публикацию HTTP/OData, mapping и восстановление. До старта подтвердите доступ
  кандидата к официальному дистрибутиву и лицензии; при внешней блокировке помогите
  с законным доступом. Готовый стенд выдавать не требуется. См. `fullstack/ONEC_SETUP.md`.
- **Удалённая среда ML/QA:** при несовместимости компьютера кандидата нужно предоставить
  проверенный отдельный стенд. Для full-stack допустим локальный запуск 1С или VM;
  согласуйте совместимую машину до начала отсчёта.

Ключи не коммитить. Учебные demo-пароли в Compose предназначены для localhost.
При удалённой выдаче используйте приватный доступ и отдельное окружение кандидата.
Текущие порты привязаны к 127.0.0.1.

## Приёмка стартового комплекта

1. Извлечь архив в новую папку и запустить по её README.
2. Для ML/QA выполнить `npm run preflight` внутри контейнера agent.
3. Для QA создать учебный логин, войти в браузере и отправить сообщение
   через alice-success / interview-mock. Проверить результат и JSONL.
4. Заполнить MODEL_* и проверить mode=real, остаток квоты и tool calling.
5. Для full-stack до старта проверить доступ к дистрибутиву/лицензии и совместимую
   машину. Сам запуск 1С выполняет кандидат: до 4 часов подготовки плюс 12 часов
   разработки. Эталонные данные и сброс базы проверяются при приёмке решения.
6. Зафиксировать выданный commit/архив и окружение; только после этого начать отсчёт.

## Границы стартового кода

В ML/QA намеренно присутствует учебный дефект в адаптере. Зелёный инфраструктурный
preflight означает работоспособность стенда, а не корректность всех бизнес-сценариев.
Кандидат пишет требуемую регрессию/evaluator/skills, не получает готовое решение.

QA-папка содержит только своё условие и нейтральную документацию. Не выдавайте весь
монорепозиторий: ML/PDF и ML/README раскрывают дефект. Не публикуйте эталонное решение
рядом с кандидатским пакетом. Корневые PDF совпадают с актуальными PDF в папках соответствующих заданий.

LibreChat UI закреплён на v0.8.0; учебный backend использует отдельно закреплённый
@librechat/agents 3.9.8 через custom endpoint. Это явно описано в кандидатском контракте.
Не требуется искать дефект upstream или настраивать Agent Builder.

## Где кандидат работает и сдаёт результат

Кандидат ведёт работу в отдельном репозитории своего GitHub-аккаунта, начиная
со стартового комплекта своего задания и сохраняя историю коммитов.
До выдачи сообщите GitHub-аккаунт проверяющего для приглашения в приватный репозиторий.
Публичный репозиторий также допустим. При сдаче получите ссылку и финальный commit SHA,
проверьте доступ и запускайте решение именно на этом коммите.
Архив или patch без собственного GitHub-репозитория не считается полной сдачей.
